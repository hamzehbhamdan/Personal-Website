### 1. `lib/dashboard/useAppState.ts:44` — Mutations made before the initial GET resolves persist a full-replace PUT built from the empty seed, wiping the user's entire server-side doc.

> **FIXED** (Stage 1, commits 307994b, 50711a7, c1cef87, 9a0d632) — useAppState buffers pre-load edits and replays them onto the freshly-loaded server doc (no seed-wipe PUT); BrainView's intent effect is gated on `loaded`. *Category: data-loss · Area: components-people-brain*

**Problem.** useAppState seeds local state with the empty seed and loads the real doc asynchronously (lines 11-18), but update() (line 44) is callable immediately and persist() PUTs the whole document (app/api/state PUT is a full upsert replace). PeopleView avoids the UI half by rendering 'Loading...' until loaded, but the hook itself has no guard.

**Suggested fix.** Fix in the hook so all four app docs are covered: in useAppState, while !loaded have update() apply the updater to local state for optimistic UI but also push it onto a pendingRef queue and skip persist(); in the load effect, take base = fetched doc (or seed if empty), replay the queued updaters in order, setState the result, and persist once if the queue was non-empty. ### 6. `components/dashboard/ui/Modal.tsx:40` — Any backdrop click or Escape instantly discards unsaved form state in every editor modal, including when a text-selection drag that started inside the dialog ends over the backdrop.

> **FIXED** (Stage 1, commit 5ad9977) — the Modal closes only when the pointer press STARTED on the backdrop (text-selection drags no longer close it); `confirmClose` dirty-guard on NoteEditor/ContactEditModal routes backdrop, Escape, and × through a confirm. Stacked-modal Escape preserved.

*Category: data-loss · Area: components-people-brain*

**Problem.** The backdrop closes via onClick with `e.target === e.currentTarget`, and Escape always calls onClose, with no dirty check anywhere. Per the UI Events spec, a click's target is the nearest common ancestor of mousedown and mouseup targets — so selecting text inside NoteEditor's textarea or ContactEditModal's Notes field and releasing the mouse just past the dialog edge fires a click whose target IS the backdrop, closing the modal. All long-form editors mount their state locally (ContactEditModal, GroupEditModal, NoteEditor, CrmSettingsModal's voice form, LearnVoiceModal's distilled-summary edit), so a 10-minute note or a fully filled contact form is lost with no confirmation and no recovery.

**Suggested fix.** Two layers, the first of which is the unambiguous bug fix and requires no API change: in Modal.tsx track where the press started and only close when both press and release were on the backdrop — add `const downOnBackdrop = useRef(false);` and on the backdrop div: `onPointerDown={(e) => { downOnBackdrop.current = e.target === e.currentTarget; }}` and `onClick={(e) => { if (e.target === e.currentTarget && downOnBackdrop.current) onClose(); downOnBackdrop.current = false; }}` (resetting the ref after every click so a stale true from a previous backdrop press cannot leak into a later drag-out click). Second layer (product decision, per-caller): add an optional `confirmClose?: () => boolean` (or `isDirty`) prop to Modal, checked in both the Escape handler (via a ref, like onCloseRef) and the backdrop/close-button paths, and wire it up at least in NoteEditor and ContactEditModal to window.confirm (or a styled prompt) when the form differs from its initial values. Alternatively, persist NoteEditor drafts to localStorage keyed by note id. No test suite impact: no test under /test references Modal or these components.

### 69. `middleware.ts:10` — Any path containing a dot bypasses the auth gate entirely, and middleware is the ONLY protection for dashboard pages (no server-side check in app/dashboard).

> **FIXED** (Stage 3, commit f9b887b) — Middleware's `pathname.includes(".")` auth-gate bypass is replaced with a closed static-asset extension allowlist (`isStaticAsset`), so a dotted PAGE path no longer skips authentication.

### 70. `public/playground/mcp-injection-lab/index.html:544` — Chart.js is loaded from cdn.jsdelivr.net with no Subresource Integrity attribute, on a page that (per the live-header check) receives no CSP, so a CDN compromise executes arbitrary JS on the hamzehhamdan.com origin.

> **FIXED** (Stage 3, commit 5f7d4a6) — Chart.js is now vendored (self-hosted at `./vendor/chart.umd.min.js`) instead of loaded from a third-party CDN, removing the external dependency (SRI unnecessary for a same-origin file).

*Category: supply-chain · Area: config-infra-security*

**Problem.** `<script src="https://cdn.jsdelivr.net/npm/chart.js@4.4.4/dist/chart.umd.min.js"></script>` has no `integrity`/`crossorigin` attributes. Because Netlify serves this static file without the next.config CSP (confirmed live), there is no script-src restriction as a backstop: if jsdelivr or the chart.js package is compromised (as happened with polyfill.io in 2024), attacker JS runs on the public site origin — defacement/phishing on a personal-brand domain (dashboard cookies are host-scoped to my.hamzehhamdan.com and HttpOnly, so they are not directly exposed, but any visitor to the page is). Note the inverse hazard too: if headers ever DO start applying to static assets (e.g., a naive 'fix' of finding 1, or serving via `next start`), the current CSP (`script-src 'self' 'unsafe-inline' https://plausible.io`) silently breaks Chart.js and the Google Fonts loads on lines 12-14.

**Suggested fix.** Preferred: self-host the library — copy dist/chart.umd.js from the npm chart.js@4.4.4 tarball to public/playground/mcp-injection-lab/vendor/chart.umd.js and change line 544 to <script src="./vendor/chart.umd.js"></script>. This removes the external script dependency entirely and keeps the page working if the site CSP (script-src 'self' ...) ever starts applying to static assets. Alternative (minimal): do NOT add integrity to the current .min.js URL — jsdelivr's .min.js is a dynamically generated artifact whose banner explicitly warns against SRI, so the hash could silently break (and app.js's `typeof Chart !== 'undefined'` guard would make the charts vanish without an error). Note: the Google Fonts stylesheets on lines 12-14 cannot use SRI (UA-dependent CSS); self-host the two font families as well if full CSP-compatibility/no-external-deps is the goal. Neither change can affect the vitest suite — nothing in test/ or app/ references this static page.
